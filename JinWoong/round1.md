# Pandas란 무엇인가?
    - Python에서 데이터를 조작하고 분석하기 위해 사용하는 라이브러리
    - 행과 열로 이루어진 데이터 객체를 만들어낼 수 있다!

# Pandas 전처리를 왜 할까?
    - 분석 및 모델링을 올바르게 하기 위한 선행 작업
    - 결측값 처리, 중복 처리, 데이터 타입 변환, 이상값 처리, 문자열 처리, 인코딩, 스케일링 등등 데이터 분석에 필요한 모든 작업이다.

    - 전처리가 올바르지 않으면?
        1. 결측값 방치 : 모델 학습 오류나 편향된 결과를 일으킨다.
        2. 이상값 방치 : 평균 및 분산을 왜곡하고 모델 성능을 저하한다.
        3. 스케일 미조정 : 특정 변수가 결과를 독점한다.
        4. 중복 데이터 : 특정 패턴이 과대 학습
        5. 타입 불일치 : 연산 오류가 발생하고 모델 입력이 불가하다.
    
# 결측값이 뭘까?
    - 설문 조사, 센서 측정, 데이터베이스 기록 등에서 수집되지 않았거나 값이 비어있는 데이터
    - 프로그램 상에서는 'NaN' 또는 'Null'로 표시된다.

# dropna() vs fillna()
    - 개념 정의
        dropna() : 빈 값(NaN or Null)이 있는 행을 삭제한다.
            ex. DataFrame.dropna() -> NaN 또는 Null이 있는 행이 삭제된다.

        fillna() : 빈 값(NaN or Null)이 있는 행에 데이터를 채운다.
            ex. DataFrame.fillna(0) -> NaN 또는 Null을 () 안의 값인 0으로 채운다.
            ex. DataFrame.fillna(method='bfill') -> NaN 또는 Null을 아래 행 값으로 채운다.
            ex. DataFrame.fillna(method='ffill') -> NaN 또는 Null을 윗 행 값으로 채운다.
    
    - dropna()와 fillna()는 둘 다 결측치를 다루는데, 어떤 상황에서 각각을 선택해야 하나요?
        dropna() : 
            1. 결측 비율이 낮아 삭제해도 표본 크기에 영향이 적을 때
            2. 결측 발생이 다른 데이터와 무관한 순수 우연일 때
                ex_1. 설문 중 인터넷이 끊겨 데이터 누락
        fillna() : 
            1. 해당 행이 사라지면 안될 때
            2. 결측 자체가 의미를 가질 때 : fillna('unknown') 등으로 대체

    - 데이터가 '사라지는 것'과 '채워지는 것'의 차이가 분석 결과에 미치는 영향을 예를 들어 설명해주세요.
        dropna()
            1. 표본 수 감소
            2. 실제 데이터의 값만 남겨 데이터 진정성 보존
        fillna()
            1. 표본 수 유지
            2. 추정치로 원래 분포를 왜곡 가능성 있음

# 실수 포인트
df.dropna()를 실행했는데 원본 데이터프레임은 그대로인 경우가 있습니다. df = df.dropna() 또는 df.dropna(inplace=True) 중 하나를 써야 하는데, 초보자는 왜 이 부분을 자주 놓칠까요?
    1. 파이썬을 배울 때 처음 익히는 list.append(), list.sort() 같은 메서드는 객체를 직접 바꾸고 끝납니다.
    2. pandas는 정반대로 "함수형" 스타일이 기본이라 호출 결과를 받아써야 합니다.
    3. df.dropna()를 실행하면 화면(노트북)에 결과가 보이니까 적용됐다고 착각하게 된다.
    4. 보이는 건 반환값일 뿐 원본은 그대로이다.

    즉, 원본 데이터프레임 변경 시 반드시 df = df.dropna() 또는 df.dropna(inplace=True)로 써야 합니다.
    
inplace 파라미터의 동작 원리를 설명해주세요.
    inplace=False는 객체를 새로 만들어 반환하고, inplace=True는 같은 객체의 내부 데이터를 갈아끼운다. 

    ex_
        id_before = id(df)
        df.dropna(inplace=True)
        id_after = id(df)
        # id_before == id_after  → True (같은 객체)

        id_before = id(df)
        df = df.dropna()
        id_after = id(df)
        # id_before == id_after  → False (다른 객체)

# 응용
실제 고객 데이터에서 결측치와 중복 제거 순서를 바꾸면 최종 결과가 달라질 수 있습니다. 어떤 경우에 순서가 중요하고, Azure ML 파이프라인에서 이 전처리 단계를 설계할 때 고려해야 할 점은 무엇인가요?
    중복 제거 -> 결측 처리

    ex_
    이름, 이메일, 구매액
    홍길동, hong@mail.com, 50000 (행 A: 완전)
    홍길동, Null, 50000 (행 B: 이메일 누락)
    
        - dropna를 먼저 하면 → 행 B가 제거되고, 완전한 행 A가 남습니다.
        - drop_duplicates를 먼저 하면 → 어떤 행을 "중복"으로 볼지에 따라 행 A가 지워지고 결측 있는 B가 남을 수 있고, 그 뒤 dropna가 B마저 지우면 고객이 통째로 사라집니다.
